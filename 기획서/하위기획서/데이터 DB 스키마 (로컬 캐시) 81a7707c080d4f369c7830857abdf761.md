# 데이터/DB 스키마 (로컬 캐시)

## 데이터/DB 스키마(초안)

### 1) 로컬 SQLite (캐시/설정/로그)

권장: EF Core + Migrations

#### 테이블: Parts

- Id (TEXT, PK)
- Category (TEXT) // Cpu, Mainboard, Ram, Gpu, Storage, Psu, Case, Cooler
- Name (TEXT)
- Manufacturer (TEXT)
- Price (INTEGER or REAL)
- Stock (INTEGER)
- SpecJson (TEXT) // 카테고리별 스펙 JSON
- ImageUrl (TEXT)
- Model3DPath (TEXT)
- PowerConsumptionW (INTEGER, nullable)
- SearchKeywords (TEXT) // 정규화(공백/특수문자 제거, 소문자)
- UpdatedAt (TEXT ISO)

인덱스:

- idx_parts_category(Category)
- idx_parts_searchkeywords(SearchKeywords)
- FTS5(선택): PartsFts(Name, Manufacturer, TagsText)

#### 테이블: Tags

- TagId (TEXT, PK)
- TagName (TEXT) // CPU, DDR5, 게이밍
- TagGroup (TEXT) // Category, Spec, UseCase
- UpdatedAt (TEXT ISO)

#### 테이블: PartTags (N:M)

- PartId (TEXT, FK -> [Parts.Id](http://Parts.Id))
- TagId (TEXT, FK -> Tags.TagId)
- PK(PartId, TagId)

#### 테이블: Benchmarks (선택)

- PartId (TEXT, FK)
- Score (INTEGER)
- Source (TEXT)
- UpdatedAt (TEXT ISO)

#### 테이블: Builds (최근 견적 저장)

- BuildId (TEXT, PK)
- Title (TEXT) // 자동: “2026-08-26 게이밍”
- BuildJson (TEXT) // SelectedParts + 계산 결과 스냅샷
- CreatedAt (TEXT ISO)

#### 테이블: AppSettings

- Key (TEXT, PK)
- Value (TEXT)

#### 테이블: AppLogs (선택)

- Id (INTEGER, PK AUTOINCREMENT)
- Level (TEXT)
- Message (TEXT)
- CreatedAt (TEXT ISO)

### 2) 서버 API 데이터 모델(개념)

- Product/Part: Parts와 동일 필드 + 판매지수/리뷰요약/벤치마크
- Order:
    - OrderId
    - Customer
    - Build(선택 부품 목록 + 가격)
    - Payment(PG 토큰/승인 정보)
    - Status
    - CreatedAt
